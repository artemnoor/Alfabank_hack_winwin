## Нормативность

MUST/«обязательно» — критерий приёмки. MAY/«допускается» — возможность без обязательства. Изменения утверждённой архитектуры требуют отдельного решения; новые операции не добавляются автоматически.

OpenAPI определяет форму данных. Текстовые документы определяют семантику, межполевые ограничения, права и эффекты. При противоречии реализацию останавливают на конкретном конфликте и исправляют спецификацию; разработчик не выбирает удобную трактовку.

В текущем пакете OpenAPI — нормативный снимок. При реализации создаются Pydantic-модели, экспорт которых должен семантически совпасть с ним. Затем модели становятся источником генерируемых схем; изменение снимка проходит review. Два независимо редактируемых источника схем не допускаются.

## Готовность

- Framework Ready: 25 операций, инфраструктура, Playground, изоляция и все обязательные проверки работают.
- Algorithm Ready: конкретная real-реализация прошла согласованную независимую оценку качества.
- Product Ready: известный кейс, полезность, эксплуатационные и пользовательские требования подтверждены.

Framework Ready не требует готовой LLM. Смешанный сценарий использует как минимум реальную детерминированную `Documents.prepare` и mocks аналитики. Все команды и чтения mocks работают на согласованном изолированном состоянии.

## Ограничение объёма

25 исполняемых операций; один backend, один frontend, одна PostgreSQL для локального окружения; файловые артефакты на локальном диске. Системные маршруты метаданных не становятся новыми исполняемыми операциями.

Вне этапа: банковские действия, закрытые данные, реальная доставка уведомлений, универсальная оркестрация, параллельные workflow, брокер событий, Redis, Neo4j, Kubernetes, векторная БД, отдельный observability-кластер, обязательные облачные сервисы. Добавление зависимости обосновывается конкретным требованием и тестом.
