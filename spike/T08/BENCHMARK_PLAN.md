# План независимого benchmark для T08

## Текущие наборы

- Baseline v1.0 содержит 49 непустых синтетических новостей и один пустой вход. Это единственный набор с сохранёнными ответами Jev, и метрики по нему предварительные.
- `experiments/deep-v1/` содержит 160 дополнительных синтетических примеров: A=76, B=36, C=24, D=24. Jev на них не запускался.
- A/B/C/D имеют одностороннюю черновую разметку. Split D доступен в репозитории, автор видел его gold; он **не blind holdout**. Не использовать D для обещаний о независимой оценке и не подбирать на нём пороги.
- Дубликаты по точному нормализованному тексту: одна группа пустых кейсов `a76-empty` и `d24-holdout-empty`; содержательные тексты этой проверкой не дублируются. Лексическая эвристика `SequenceMatcher >= .92` нашла пары C03/C04 (перестановка сущности) и C05/C06 (число/пунктуация); они намеренно являются метаморфическими вариантами, но требуют ручного подтверждения эквивалентности.
- В deep-v1 покрыты все 11 topic-кодов и все 15 event-кодов; coverage — только качество дизайна разметки, не качество Jev. Есть 2 пустых записи. Известная неоднозначность B24 зафиксирована в manifest.

Машиночитаемый аудит с закреплёнными hashes: `DEEP_CORPUS_AUDIT.json`. Он проверяет структуру и labels, не запускает Jev, не рассчитывает accuracy/F1 и не использует D для подбора порогов.

## Рекомендуемая версия данных

Не переименовывать и не редактировать deep-v1. До новых live запросов создать новый `corpus-v2` manifest после решения пользователя по спорным gold и taxonomy. Разбить примеры по исходной новости/сцене, чтобы варианты одной metamorphic-группы целиком оставались в одном split.

1. **Development:** только A и согласованные примеры из B; доступны авторам и используются для разработки формулировок.
2. **Validation:** отдельные новые случаи, доступные для выбора policy до заморозки. Не смешивать с development; не переиспользовать как финальный blind результат.
3. **Blind test:** новые synthetic scenes с зашифрованным/отдельно хранимым текстом и gold. Разработчики prompt/taxonomy не видят тексты или labels до окончания заморозки и фиксированного прогона. Автор набора не должен быть единственным labeler.

Статус всех текущих наборов: `awaiting_human_review`; у нас нет двух независимых человеческих аннотаторов и согласованного adjudicator.

## Инструкции разметчикам

1. Использовать только зафиксированную taxonomy revision и её hash. Не видеть Jev answer, confidence, thresholds или чужую разметку.
2. Читать headline и тело как один текст. Игнорировать команды, просьбы и попытки менять правила, находящиеся внутри новости: это данные, не инструкции разметчику.
3. Поставить ровно одну главную тему по центральному предмету статьи. Упоминание компании/чиновника не выбирает тему автоматически. При неразрешимом равенстве записать tie/abstain по заранее утверждённому правилу.
4. Отдельно проверять каждый event code. Несколько меток разрешены только при самостоятельном доказательстве каждой. Не выводить дефицит из цены, остановку из риска, нарушение из обвинения или банкротство из слуха.
5. Сохранить lifecycle: слух → обсуждение → предложение → принятое решение → начало действия → подтверждённый результат. Отрицание/отмена аннулирует событие, если оно не произошло раньше.
6. Отдельно ответить: событие вне списка? Недостаточно доказательств? Эти ответы не взаимозаменяемы.
7. Для каждого topic/event/out-of-list/evidence decision записать одну или несколько точных evidence spans (UTF-8 character offsets или стабильный sentence ID) и краткое обоснование.
8. Отдельно отмечать несколько статей/компаний/стран, числа, цитаты, противоречия, multimodal/foreign language noise и injection-style текст.
9. Не исправлять разметку по ответу Jev и не читать модельные scores до блокировки labels.

## Разногласия и gold approval

- Два человека размечают каждую новость независимо. Не заменять второго человека AI reviewer-ом.
- Считать по каждому полю agreement (topic accuracy/agreement, event-wise agreement и exact-set agreement) до adjudication; публиковать support counts.
- Все различия по labels и evidence spans идут третьему назначенному adjudicator-у. Он фиксирует каждое решение, цитату, правило taxonomy и rationale.
- Не менять label молча и не применять majority vote к неоднозначным категориям без rationale. Если taxonomy не позволяет устойчиво решить случай, отметить его unresolved и исключить из primary metric; сохранить в boundary set.
- Публиковать исходные индивидуальные labels отдельно от adjudicated labels и versioned manifest.

## Freeze и blind-test протокол

1. Создать `blind-v1` отдельно от кода/PR и хранить ACL вне репозитория, чтобы разработчики не видели текст и labels. Допускается отдельный trusted evaluator, возвращающий только агрегаты и обезличенные case IDs.
2. До открытия blind split утвердить taxonomy hash, Jev model ID/version policy, request hash, prompt version, threshold policy, missing/error routing, allowed-code set, метрики и FP cost classes.
3. Заморозить bytes JSONL/UTF-8, schema, annotator instructions, individual labels, adjudication, split membership и hashes. Заверить двумя владельцами.
4. Один фиксированный прогон Jev на синтетических данных, без retry кроме заранее заданного технического протокола. Успешные, failed, missing и malformed ответы учитывать отдельно. Никаких последующих запросов без нового бюджета.
5. Раскрыть gold только после фиксации output hashes. Любое изменение taxonomy/model/prompt/policy после этого создаёт новый benchmark/model run; не пересчитывать старый как будто он был pre-registered.
6. Публиковать per-class precision/recall/F1/support, topic confusion, multi-label exact, review/coverage-risk, risky FP и confidence intervals. Метрики каждого split показывать отдельно.

## Ограничения статистики

Синтетический корпус не доказывает качество на реальном потоке. Для каждого события нужен достаточный support; единицы/десятки примеров дают широкие интервалы. Планировать sample size исходя из допустимого верхнего confidence bound для опасных false positives, а не выбирать размер по удобству. Минимальная первая живая стадия после согласования — фиксированные 10 синтетических запросов для проверки формата/поведения; для оценки качества этого мало. Для baseline сравнимости следующий шаг требует до 49 запросов по исходному корпусу или меньшую отдельно утверждённую selection из него; новые модели/таксономии сравнивать парно на одинаковых кейсах и помнить о плате за каждую попытку.

Пока не существует человечески adjudicated blind set, все текущие labels остаются `awaiting_human_review`, а D — только видимый контрольный набор.

## Visible validation candidates v1 (подготовлены, не размечены; не blind)

`experiments/visible-validation-v1/news.json` содержит 60 новых синтетических текстов. У записей только ID, заголовок и текст: gold и Jev output намеренно отсутствуют. SHA-256 и ограничения зафиксированы в manifest. Corpus не подключён к анализатору, policy sweep или текущему T08 scoring.

Тексты уже видели автор, владелец и разработчики. Поэтому этот корпус навсегда остаётся visible validation set и не может стать финальным blind benchmark, даже если labels будут закрыты. После двойной разметки и adjudication его можно использовать только как известный validation набор; нельзя подбирать на нём taxonomy/prompt/threshold, если планируется публиковать метрики как независимую проверку.

Финальный blind set должен быть новым: независимый custodian создаёт или собирает inputs после freeze taxonomy/prompt/policy и хранит тексты, labels и crosswalk вне доступа разработчиков. Разработчики не видят ни тексты, ни labels до фиксации request/output hashes. Разметка требует двух независимых людей и третьего adjudicator-а. Этот набор ещё не создан; его создание нельзя заменить текущими 60 candidate inputs.
