# T08 spike: классификация новостей через Jev

**Статус:** изолированный эксперимент; в production не подключён. Папка содержит прототип и результаты тестирования, предназначенные для последующего рассмотрения и возможной интеграции в основной код после завершения live-проверки, независимой приёмки и согласования таксономии. Автоматического переноса или merge в `main` нет.

## Что проверяется

Единственный классификатор этого эксперимента — **Jev**. Список категорий и определения заданы проектом, а не генерируются моделью. Черновик `taxonomy.json` содержит 10 именованных общих тем и вариант `other_uncertain` (всего 11 вариантов Choice), а также 15 бизнес-событий.

Для одной главной темы используется Jev `Choice`. Для каждого из 15 бизнес-событий задаётся отдельный независимый Jev `Noul`; поэтому одна новость может иметь несколько меток событий. Ещё один `Noul` проверяет подтверждённое коммерческое или операционное событие вне списка; макроэкономическая мера без прямо описанного делового события не считается таким событием. Отдельный `Noul` выявляет расплывчатые, неполные, спекулятивные, противоречивые или неподтверждённые сведения и направляет их на review. Итого запрос содержит один `Choice` и 17 независимых `Noul` вопросов. Если тема или событие неясны, результат направляется в `uncertain`/`other`, без создания новых категорий. Пустой ввод отсекается локально.

В версии таксономии `0.3.0-spike` уточнена граница `legal_enforcement`: метка требует отдельного юридического развития сверх основного события. Обычное открытие процедуры банкротства остаётся только `insolvency_default`; отдельное заявление кредитора после дефолта даёт обе метки; подтверждение исполнения санкционного решения остаётся `sanctions`.

`corpus.json` содержит **49 вымышленных русскоязычных новостей и один пустой ввод** (50 тест-кейсов). Метки написаны вручную и используются только для оценки: они не добавляются в запросы Jev. Каждая из 15 категорий событий имеет не менее двух положительных примеров. В наборе есть одиночные события, сочетания событий, неопределённые сообщения, отрицания, неподтверждённые слухи, пример с инструкцией внутри новости, событие вне списка и текст без бизнес-события. Набор полностью синтетический и не содержит реальных публикаций или пользовательских данных. Он включает явное макроэкономическое отрицание для unlisted-сигнала, событие вне списка, неоднозначную неполную заметку и дополнительный экологический пример без бизнес-события.

Тексты таксономии и корпуса закреплены SHA-256 в harness. Live-клиент откажется работать, если их байты изменены. Он также принимает только заранее выведенные хеши точных запросов из проверенного корпуса, использует только alias `jev-latest`, проверяет точную версию Jev в ответе и отправляет каждый разрешённый запрос не более одного раза.

## Границы эксперимента

- Код находится только в `spike/T08/`. Он не регистрирует production implementation и не меняет API, CLI, Playground, OpenAPI, fixture registry или зависимости приложения.
- IPTC, GDELT/CAMEO, Event Registry и RavenPack использованы только как ориентиры при составлении собственного списка. Они не классифицируют новости и не поставляют модели.
- Live-режим может отправить только закреплённые синтетические новости. Реальные статьи, unknown/manual материалы и произвольный текст не принимаются.
- Для native `Choice`/`Noul` используется официальный TypeSafe System One API. Транспорт фиксирован на официальном HTTPS endpoint, без редиректов и повторов; ограничены время запроса и размер ответа.
- В отчёт попадают ID синтетического случая, оценки/метки Jev, версия модели, token usage и локальное время запроса. Текст, запрос, полный ответ провайдера, ключ и исходный текст ошибок не записываются.
- Для event/unlisted Noul оценки `≤ 0.2` считаются отрицательными, `≥ 0.8` — положительными; промежуточные требуют review. Для Noul-сигнала недостаточности данных любое значение выше `0.2` направляется на review. Choice ниже `0.5` также требует review. Все пороги экспериментальные, не оптимизированы и не откалиброваны для новостей; это не production policy.

## Состояние живого доступа

Официальный `GET /v1/models` завершился HTTP **451**. Затем один `POST` с синтетическим кейсом `e01-supply-rail` был отклонён HTTP **451** в версиях таксономии `0.1.0-spike` (`synthetic-ru-news-48`) и `0.2.0-spike` (`synthetic-ru-news-50`); оба безопасных отчёта сохранены в `results/` вместе с версиями и хешами использованных таксономий. В ответах Jev не было, полные наборы не запускались. Текущая версия `0.3.0-spike` добавлена после этих попыток и к API ещё не отправлялась. Качество модели на русском **не измерено**. HTTP 451 сам по себе не позволяет сделать вывод о валидности ключа или состоянии аккаунта.

Альтернативный маршрут не использовался: совместимость его chat API с native Jev `Choice`/`Noul` не подтверждена. После восстановления доступа к официальному API можно повторно запустить live-пилот тем же закреплённым корпусом. Текущие успешные офлайн-тесты проверяют harness и синтетические метрики, но не точность модели. Prompt-injection тест подтверждает только неизменность фиксированного списка категорий; устойчивость Jev к инъекциям остаётся непроверенной.

## Запуск

Из корня репозитория:

```powershell
python spike/T08/run_spike.py
python -m unittest discover -s spike/T08 -p test_spike.py -v
```

Офлайн-проверки валидируют закреплённую таксономию и корпус, допустимые коды и gold-разметку, форму Choice/Noul вопросов, строгую проверку ответов, независимые метки нескольких событий, отдельный сигнал недостаточности данных, unlisted-границу, пустой ввод, отказ неизвестной категории, prompt-injection пример как недоверенный текст, фиксированную модель, авторизацию точных запросов, одноразовую отправку, скрытие ошибок и запрет редиректов. Тесты транспорта используют только локальные подмены и не обращаются к сети.

Когда официальный endpoint доступен, запуск ограничен 49 запросами по 49 закреплённым новостям:

```powershell
python spike/T08/run_spike.py --live --max-calls 50
```

Ключ должен быть уже предоставлен защищённым окружением Codex; команда не просит вводить или печатать его. Ошибка первого сетевого запроса останавливает прогон, автоматических повторов нет. Отчёт с безопасно обработанными ответами сохраняется новым файлом в `spike/T08/results/`. Полный live-пилот остаётся небольшой синтетической проверкой, а не доказательством статистического качества или готовности к production.

## Что решить до возможной интеграции

1. Согласовать состав и границы предложенных категорий.
2. После успешного live-прогона вручную оценить ошибки, распознавание неопределённости и threshold sweep. Не подбирать production thresholds по малой синтетической выборке.
3. Отдельно согласовать преобразование оценок Jev в нормативные `TopicScore`/`event_hints`; этот spike не заявляет соответствие output DTO.
4. Интеграцию в существующий `Understanding.classify`, Dependency Gateway, policy и Run History проводить только как отдельную работу T08 с контрактными, replay и egress-тестами.
5. Не отправлять реальные/unknown/manual данные во внешний API до подтверждения trusted-source policy gate и разрешённого egress.

- [TypeSafe Choice](https://docs.typesafe.ai/primitives/choice) и [TypeSafe Noul](https://docs.typesafe.ai/primitives/noul) — семантика одиночного выбора и независимых yes/no-вопросов.
