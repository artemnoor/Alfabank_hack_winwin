# T08 → DeepSeek → T09: эксперимент извлечения фактов

Этот spike добавляет extraction-only адаптер после T08 Policy v2.1. Jev остаётся
единственным компонентом, который выбирает event-категорию. DeepSeek получает
текст и уже выбранный T08-кандидат, а извлекает только текстовые факты и цитаты.

## Открыть offline-демо

Из корня репозитория:

```powershell
py -3 spike/T08/fact_extraction/offline_demo.py
```

Демо использует сохранённый Jev ответ для `nb-003` и отдельный вручную
подготовленный fixture ответа extractor. Это **не ответ DeepSeek**. Команда
работает локально, ключ не читает и сеть не использует.

## Порядок обработки

См. [FLOW.md](FLOW.md). Для каждого Jev-кандидата, разрешённого Policy v2.1,
создаётся отдельный запрос. Вывод DeepSeek проходит строгую Pydantic-схему;
каждая выданная цитата и значение должны находиться в тексте ровно в одном
месте. Неоднозначные/отсутствующие цитаты приводят к отказу всего ответа данного
кандидата. Событие-код в модельном schema отсутствует — код прикрепляет только
T08.

Если извлекатель указывает компанию, он также указывает её роль: субъект,
участник-действующее лицо, затронутая сторона, источник сообщения, просто
упоминание или неизвестно. Связь добавляется в `EventMention` только для первых
трёх ролей; reporter/mentioned/unknown остаются неразрешёнными и попадают в
`missing_data`. Название компании и формулировка события должны иметь одну и ту
же точную цитату в одном предложении. Это проверка структуры и извлечённой роли,
а не доказательство истинности: результат остаётся кандидатом, `confirmed`
недоступен.

В `ExtractionOutput` попадают `EventMention`, исходные `EvidenceSpan`,
неразрешённые сущности и `missing_data`. Относительное время вроде «со вчерашнего
вечера» сохраняется как точный текст, но не превращается в календарную дату.
Извлекатель никогда не выставляет `confirmed`.

## Live API

Live-вызовы отключены по умолчанию. Код закреплён на Polza model ID
`deepseek/deepseek-v4-flash` и endpoint `https://polza.ai/api/v1/chat/completions`.
Чтобы включить вызовы в будущем, потребуется отдельное разрешение пользователя,
явно ограниченный бюджет и `POLZA_AI_API_KEY` в окружении процесса. Эта поставка
не делала DeepSeek-запросов и не читала переменную с ключом.

**Ограничение идентичности модели:** каталог Polza показывает этот ID как
DeepSeek V4 Flash. Однако документация DeepSeek от 10 сентября 2026 сообщает,
что старый V4 Flash снят с обслуживания и идентификатор `deepseek-v4-flash`
временно маршрутизируется на V4.1 Flash. Без подтверждения Polza или разрешённого
live-запроса нельзя установить, какой именно checkpoint будет обслуживать
агрегатор. Поэтому прототип намеренно не переключает ID на `deepseek-flash` и
не заявляет, что реальная модель проверена.

Документы проверены 15 октября 2026: [каталог Polza](https://polza.ai/models/deepseek/deepseek-v4-flash),
[инструкция Polza для DeepSeek API](https://polza.ai/providers/deepseek) и
[журнал релизов DeepSeek](https://api-docs.deepseek.com/updates/?release=deepseek-coder).

## Границы контракта

- `ExtractionInput` и `ExtractionOutput` используют shape существующего
  Framework v1 OpenAPI; OpenAPI не изменялся.
- Experimental binding `event-schema-spike-v1.json` — локальная заглушка
  кодового реестра для формы DTO. Он имеет `experimental-not-registered` статус
  и не является нормативной T09 EventSchemaRegistry.
- `EvidenceSpan` — локальные указатели с `prepared_hash`. Для реальной передачи
  дальше их ещё должен зарегистрировать Evidence owner, после чего Events
  применит собственную policy.
- В репозитории нет runtime T09. Эта работа показывает совместимый DTO, но не
  исполняет `Events.propose_resolution`.
- Внешний egress в этом spike разрешён только доверенным synthetic input.
  Unknown/public данные закрываются до вызова. Никакие производственные
  материалы не отправляются.

См. [TEST_REPORT.md](TEST_REPORT.md) для выполненных проверок и ограничений.

## Повторяемость

Используются сохранённые файлы Jev pilot и versioned experimental binding.
`offline_demo.py` не перезаписывает корпус, сохранённые оценки или отчёты Jev.
